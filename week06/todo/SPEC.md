# 할 일 관리 웹앱 스펙

## 1. 개요

할 일을 추가하고, 완료 표시하고, 삭제하는 웹앱이다. 로그인은 없다.

할 일 하나는 다음 세 가지만 가진다.

| 항목 | 내용 |
|---|---|
| 제목 | 1자 이상 100자 이하의 문자열 |
| 완료 여부 | 완료 / 미완료. 새로 추가하면 미완료 |
| 만든 시각 | 추가한 시각. `YYYY-MM-DD HH:MM:SS` 형식 |

## 2. 기술

- Python Flask
- SQLite (파이썬 내장 `sqlite3` 모듈). 파일 이름은 `todo.db`
- 화면은 HTML과 CSS만 쓴다
- 테스트는 Flask의 `test_client`로 한다

## 3. 파일 구성

```
todo/
├── app.py              # Flask 앱과 라우트
├── db.py               # 초기화, 목록 조회, 추가, 완료 전환, 삭제
├── test_app.py         # 6절의 테스트
├── templates/
│   └── index.html      # 목록과 추가 입력창
└── static/
    └── style.css       # 화면 스타일
```

## 4. 동작 규칙

| 메서드 | 주소 | 입력 | 결과 |
|---|---|---|---|
| GET | `/` | 없음 | 200. 할 일 목록. 완료한 할 일은 목록 아래쪽에 모은다 |
| POST | `/add` | 폼 필드 `title` | 저장하고 302로 `/`에 이동 |
| POST | `/toggle/<id>` | 주소의 번호 | 완료면 미완료로, 미완료면 완료로 바꾸고 302로 `/`에 이동 |
| POST | `/delete/<id>` | 주소의 번호 | 지우고 302로 `/`에 이동 |

예외 상황

| 상황 | 결과 |
|---|---|
| 제목이 비어 있음 | 400. 저장하지 않는다. "제목을 입력하세요." 표시 |
| 제목이 100자를 넘음 | 400. 저장하지 않는다. "제목은 100자 이하로 입력하세요." 표시 |
| 없는 번호를 `/toggle/<id>`, `/delete/<id>`로 요청 | 404 |

## 5. 화면

한 화면(`/`)만 있다.

- 제목 입력창과 추가 버튼
- 할 일 목록. 한 줄에 완료 버튼, 제목, 삭제 버튼
- 완료된 할 일은 제목에 취소선을 긋는다

## 6. 테스트

`python test_app.py`로 실행한다. 테스트는 임시 데이터베이스 파일을 쓰고 끝나면 지운다.

| 요청 | 기대하는 결과 |
|---|---|
| GET `/` | 200 |
| POST `/add` title=`우유 사기` | 302, 이후 GET `/`에 "우유 사기" 포함 |
| POST `/add` 직후 | 완료 여부가 미완료, 만든 시각이 `YYYY-MM-DD HH:MM:SS` 형식 |
| POST `/add` title=100자 | 302, 저장됨 |
| POST `/toggle/1` (미완료인 1번) | 302, 1번이 완료 |
| POST `/toggle/1` 두 번 | 1번이 미완료 |
| A, B 추가 후 A 완료 | GET `/`에서 B가 A보다 먼저 나옴 |
| POST `/delete/1` | 302, 1번이 없어짐 |
| POST `/add` title=`` (빈 문자열) | 400, 할 일 0개 |
| POST `/add` title=101자 | 400, 할 일 0개 |
| POST `/toggle/999` | 404 |
| POST `/delete/999` | 404 |

## 7. 완료 전 점검

- [ ] `python test_app.py`가 전부 통과한다
- [ ] `python app.py`로 실행해 브라우저에서 추가, 완료, 삭제가 된다
- [ ] 서버를 껐다 켜도 목록이 남아 있다
- [ ] 8절의 것을 만들지 않았다
